# 출시 전 마케팅 측정 기준

2026-10-24. PR37의 이메일 접수 흐름을 기준으로 한다. 배포와 실제 수신 검증 전에는 알림 수집 운영 완료로 표시하지 않는다.

## 이벤트와 해석

| 이벤트 | 발생 시점 | 의미 |
|---|---|---|
| letter_entry_clicked | 편지 링크 클릭 | 편지 영역 이동 |
| letter_started | 편지 입력 시작 | 작성 활동 |
| letter_card_exported | 카드 내보내기 처리 | OS 저장이나 인쇄 확인 아님 |
| launch_notify_viewed | 폼이 50% 이상 보인 첫 시점 | 해당 마운트당 1회, 고유 방문자 아님 |
| launch_notify_attempted | 클라이언트 이메일·동의 검증 후 API 요청 | 재시도 포함 |
| launch_notify_submitted | API 성공 응답 | 접수 처리, 이메일 소유 확인·구매 아님 |
| launch_notify_failed | API 실패 또는 네트워크 예외 | 고정 오류 코드만 기록 |

알림 이벤트 속성은 `placement: home | product`, 실패 시 `reason`으로 제한한다. 이메일·편지·이름·원시 오류 문자열을 분석에 보내지 않는다. 기존 `NEXT_PUBLIC_LAUNCH_NOTIFY_ANALYTICS=off` 설정은 추가 이벤트에도 적용된다.

## 지표

- 동일 기간·배치에서 접수 처리 성공 비율 = submitted / attempted. 요청 기준이며 재시도와 분석 차단에 의한 누락이 있다.
- 오류 비율 = failed / attempted. 분모가 0이면 0%로 표시하지 않고 자료 없음으로 표시한다.
- 실제 신청자 수는 수신함에서 중복·철회를 제거한 합계로 따로 관리한다. API 성공 이벤트와 동일하지 않다.
- 현재 신청 데이터에는 UTM이 없다. 채널별 방문은 볼 수 있어도 채널별 고유 신청·매출 기여를 단정할 수 없다.
- 저장/시작 이벤트 비율은 서로 연결된 고유 세션 전환율이 아니다. 정의가 맞는 도구에서 같은 세션 기준으로 집계하기 전에는 활동 건수로 보고한다.

## 전환 동선과 메시지

출시 전에는 편지 체험 또는 제품 준비 내용 중 한 목적에 맞는 링크를 사용한다. 준비되지 않은 `/gift` 경로나 구매 버튼을 게시하지 않는다. 알림 기능은 처리방침, 배포 API, 운영자 수신 확인 후에 안내한다.

알림 동의는 출시 소식 안내 목적이다. 자동 환영 메일·정기 개발 소식 메일은 현재 구현에 없으며 약속하지 않는다. 제품명은 레터 올인원, 150ml는 기획 기준, 변성알코올·향료 제외는 개발 방향이다. 인쇄 카드·배송·가격·출시일은 확정 정보가 있을 때 안내한다.

## 공개 후 확인

1. 본인 소유의 테스트 주소로 동의 후 신청해 API 응답과 운영자 메일함 실제 수신을 각각 확인한다.
2. 요청 실패가 성공 화면이나 성공 이벤트로 집계되지 않는지 확인한다.
3. 폼 50% 노출, 요청, 성공/실패 이벤트가 실제 Analytics 프로젝트에 수집되는지 확인한다. 로컬 테스트만으로 수집 완료를 단정하지 않는다.
4. 테스트 신청은 운영 신청자 합계에서 제외하고 삭제한다.
5. 7일간 콘텐츠별 유입·편지 활동·접수 오류·중복 제거 신청을 동일 기간으로 기록한다. 적은 표본에서 성과 우열을 확정하지 않는다.

## 검증

회귀 테스트는 50% 미만의 최초 교차, 중복 노출 콜백, 성공과 요청의 분리, 미설정/요청제한/서버 오류, 예상 밖 오류 키, 네트워크 실패 후 재시도를 확인한다. 외부 분석·메일 발송은 테스트에서 수행하지 않는다.
